# Spec generation and operation coverage

`api/specs/sources.json` is the single source list for sync, generation and inventory. Each entry
declares Circle's exact title/version and route prefix, the module, and the official download URL.
Filenames follow the entry name. `gen:types` also generates `src/generated/*.requests.ts`, compact
per-operation query/body routing contracts used by named resources. `gen:check` checks these bytes
alongside declarations; no runtime YAML parser or spec download is added. Unsupported root body
forms fail generation visibly instead of producing a guessed routing contract.
The Admin V2 document currently has `info.version: v1`; this is
the upstream metadata, not a change to the Admin V2 API scope. The unused alternate
`scripts/spec-sync.mjs` was removed; the existing npm commands keep their names.

| Command | Network | Result |
| --- | --- | --- |
| `npm run gen:types` | None | Generate declarations from local specs; replace only changed outputs |
| `npm run gen:check` | None | Compare regenerated bytes with local declarations; exit 1 for stale/missing files |
| `npm run coverage:api` | None | Print current method/path inventory as Markdown |
| `npm run coverage:api -- --json` | None | Print structured inventory, including operation summaries and wrapper source paths |
| `npm run coverage:write` | None | Save the current inventory to [api-coverage.md](api-coverage.md) |
| `npm run coverage:check` | None | Verify the saved inventory; exit 1 for drift or missing raw routes |
| `npm run spec:check` | Circle's three public spec URLs | Compare candidate specs/types without changing tracked files; exit 1 for drift or failure |
| `npm run spec:sync` | Circle's three public spec URLs | Validate all candidates, then replace downloaded specs with their pristine bytes |

All commands exit 0 only on success. Run them from the repository root with lockfile dependencies
installed. The live check also needs Git to produce unified diffs. No install/prepare hook downloads
specs. `build` uses local source and types; `prepublishOnly` regenerates from local committed inputs
and builds. These commands do not publish, tag releases or upgrade dependencies.

## Deliberate upstream updates

Run `npm run spec:check` first. When drift exists, inspect its printed `.cache/spec-refresh-*`
directory. `before/` and `after/` contain changed inputs/outputs, each `.patch` is a unified diff,
and `README.txt` records SHA-256 fingerprints. Drift exits 1 for visibility; it is not acceptance
of the candidate. If a candidate spec introduces an unresolved schema reference, its input diff
and a generation-error diagnostic remain inspectable even though candidate types cannot be built.
A failed download or invalid candidate exits 1 with context and leaves accepted
files unchanged. Reports persist for inspection only when a diff was produced.

To accept an upstream update, run:

```sh
npm run spec:sync
npm run gen:types
npm run coverage:write
npm run gen:check
npm run coverage:check
```

Sync fetches the live URLs again, so inspect the actual resulting Git diff even after inspecting
a previous report. Review request/response changes and new/removed operations against the public
compatibility contract, add relevant contract tests and run all repository checks. Never accept
breaking changes just because generation passed. No automatic dependency update or publication
is part of refresh. `.gitattributes` keeps YAML inputs and generated declarations at LF on Windows
and Unix; no YAML is reformatted or rewritten by the generator.

## Validation and replacement

Each download has a 30-second timeout covering headers and body, a 10 MiB limit, strict UTF-8
decoding, expected content types, successful HTTP status and no redirects. Validation requires
the expected OpenAPI 3.0/3.1 identity, route prefix, nonempty operations and responses. Generation
uses pinned openapi-typescript with alphabetized output and no timestamps. Document-local refs
and examples keep the resolver offline; external refs/examples/discriminator mappings fail
explicitly rather than making hidden reads. Unresolved local refs fail generation.

Request-only object schemas with `oneOf` branches containing only inherited `required` names are
normalized in memory before declaration generation. Each branch receives those property schemas
from its parent, preserving required Auth identities and Admin message recipients with
openapi-typescript 7.10.1. Responses, downloaded YAML, explicit branch schemas and unrelated refs
are untouched. The generated unions require a branch's fields; they are not runtime schema
validation and do not establish exclusive-one matching. Fixtures and compile-only consumer calls
exercise the normalization and required inputs with `exactOptionalPropertyTypes`.

Every input is validated and every output is rendered before replacing any file. Changed outputs
are staged beside their destinations, then renamed without deleting an existing destination to
work around permissions. A handled staging/rename failure restores prior outputs and cleans
temporary files. If rollback itself fails, recovery files remain and the diagnostic requests
inspection. Replacement is atomic per file; a process crash or power loss cannot make a whole
multi-file batch transactional. Use Git to inspect/recover such an interrupted batch.

## Known schema override and inventory boundaries

Only `POST /api/admin/v2/chat_room_message_imports`, response `201`, media type
`application/json`, has an override for the missing `admin_v2_chat_room_message` reference.
Generation removes that reference in memory and yields `unknown`. A supplied official definition
automatically takes precedence, regardless of YAML/JSON formatting. The same unresolved reference
in another operation/status, or a different unresolved reference, is still an error. Fixtures test
both the omission and a future upstream correction. Downloaded YAML remains pristine.

The inventory reads operations from the specs, non-`never` raw declarations from generated `paths`,
and named wrappers from registered resource factories using TypeScript's AST. It ignores comments,
unreturned helpers and optional `never` method placeholders. Dynamic requester paths and unsupported
resource shapes fail visibly. It lists known untyped success media separately; no-content 204/205
responses are excluded. Nested free-form schemas remain as declared by upstream and are not all
enumerated in this summary. Exposure counts do not prove serialization or runtime correctness.

The current inventory records all 47 raw-only Admin operations with method/path and ownership:
task 12 has 8, task 13 has 15, task 14 has 11 and task 15 has 13. Recompute after each wrapper change
or accepted spec refresh; newly unassigned routes need explicit triage. Current counts belong to
the generated report, rather than hard-coded test expectations that would prevent adding wrappers.
